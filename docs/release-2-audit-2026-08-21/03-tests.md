# Test audit

## Result

The suite is broad, but new test volume is concentrated in large files and
several tests assert source text or reproduce the production model instead of
checking an independent observable invariant. The most important misses are
exact first-use and release paths.

## Missing blocker tests

1. **Credential bootstrap:** no test executes non-root `docker-helper init`
   with a system socket present and no credential file, then verifies that the
   token was written. This allowed `verifyCredentialToken`'s ambiguous `nil`
   result to turn first install into a false “already installed” success.
2. **CA preflight:** no test makes `computeOpenSSLHash` fail through
   `validateCAConfig` and verifies that configuration is not persisted.
3. **SELinux `/opt`:** no enforcing test proves that a root accepted by
   application policy has a file type accessible to both daemon and custom
   container domain, or that unsupported types are rejected at init.
4. **Release job:** workflow tests do not execute the isolated release job's
   dependency contract. `build-packages.sh` requires `checkmodule` and
   `semodule_package`, but the job installs neither.
5. **RPM target:** no clean Fedora/RHEL installation test verifies that the RPM
   can resolve its simultaneous AppArmor and SELinux dependencies.
6. **Confined CA source:** no acceptance test establishes whether Release 2
   requires a helper-owned readable source path or a managed import workflow
   under both MAC backends.

These tests should be added with the corresponding fixes, before broader UAT.

## Abstraction and layering findings

### `lsm_test.go`

The detector matrix already covers backend combinations, then many individual
tests repeat global seam replacement for `requireMACBackend`, confinement,
serve, and init. Consolidate around a small probe fixture and table-driven
state transitions. Preserve a small number of command/serve integration tests
for the fail-closed boundary.

### `completion_test.go`

The helper rebuilds the binary repeatedly across completion scenarios, and
many tests repeat membership checks. Cache one binary/script per test process,
test the renderer directly for most cases, and retain one Bash end-to-end test.
The helper's `string(rune('0'+cword))` encoding also assumes a single-digit
`COMP_CWORD`; use decimal formatting.

### `packaging_test.go`

This file combines installer emulation, lifecycle behavior, artifact layout,
workflow source inspection, manual/completion checks, and SELinux policy string
checks. Split by owned behavior with a shared package fixture:

- installer and uninstall behavior;
- native package lifecycle;
- artifact contents;
- release workflow;
- SELinux policy/package integration.

String checks such as the presence of `user_home_type` prove neither loadability
nor runtime access. Keep fast static checks, but make the enforcing live matrix
the authority for policy semantics.

### CA tests

The OpenSSL 3.5.7 golden hashes are valuable. Advanced canonicalization tests,
however, use production DER helpers or locally restate the same algorithm; they
are model-consistency tests rather than an independent OpenSSL oracle. Add a
build/CI differential corpus generated by supported OpenSSL versions, including
multi-valued RDNs, whitespace, non-ASCII names, and T61/BMP/Universal strings.
OpenSSL must not become a runtime dependency again.

## Verification limitation

This audit could not run `go test ./...`, `go test -race ./...`, or `go vet
./...` because the environment does not contain Go. Shell syntax checks passed;
SELinux policy compilation was also unavailable locally. The final release gate
must therefore rerun the complete test, race, vet, package-build, and enforcing
policy matrix in prepared environments.
